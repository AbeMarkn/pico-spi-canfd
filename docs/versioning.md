# バージョニング運用規約

関連: SPEC-NF-005、DESN-SW-013、DESN-SW-014。文書版は`0.1.0`。Gitタグやソフトウェアリリースを今回作成した意味ではない。

## 1. SemVer標準

[SemVer 2.0.0](https://semver.org/lang/ja/)を基本とする。公開APIが非互換ならMajor、互換性を保つ機能追加ならMinor、互換性を保つ不具合修正ならPatch。公開済みの同じ版を後から変更しない。プレリリースは`-draft.1`等、ビルド情報は`+`以降を使い、互換性番号の代わりにGit commitを扱わない。

0.y.zは初期開発段階。1.0.0は公開APIを定義した最初の正式版とし、本プロジェクトでは基本機能の実装・必要な検証と受入が完了してから付ける。設計文書を作っただけでv1.0.0や「実機検証済み」としない。

## 2. このプロジェクトの公開契約

USBプロトコル、設定schema、利用者のキー操作・ログ形式、公開Module API、要求される配線と電圧を互換性の判断対象とする。非互換なピン変更はSemVer標準そのものの規定ではなく、本プロジェクトで公開契約に含める独自規則である。基板revisionも別途記録する。

FW版、ホスト版は必要なら別々のSemVerを持ち、通信majorと設定schemaを照合する。初期開発中でも既存設定を壊す変更は明示し、0.y.zのMinor更新と移行説明を行う。1.0.0以降は非互換変更でMajorを上げる。

## 3. コミットと版の関係（独自規則）

- `feat:`は通常Minor、`fix:`は通常Patch。
- `feat!:`、`fix!:`または`BREAKING CHANGE:`があれば、接頭語より実際の互換性を優先してMajorを判定する。
- `docs:`、`chore:`、`test:`、`style:`、`refactor:`で互換性を変えないリリースは、プロジェクト規則としてPatchを使う。SemVerが全ての文書変更にPatchを義務付けているわけではない。
- 1コミットごとの版更新は要求しない。リリースに含む変更全体の最も大きい互換性影響で決める。
- 文書レビュー中はdraft番号を進める。確定した版のタグは必要な確認後に付け、未確認の予定版を実在する履歴に混ぜない。
