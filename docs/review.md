# 実装・文書セルフレビュー

文書版: `0.1.0`。2026-09-14。実施値の正本は[第1回結果](test/results/TEST-SPEC-DESN_result_001.md)。

## 要求された九つの確認観点

1. **仕様と実装詳細**: 仕様の目標を維持し、GPIO・レジスタ・API・依存版は設計／IF文書へ分離した。
2. **要求の変更防止**: Classical／FDの両方向、標準／拡張ID、4 IDの10／100／1000／10000 ms、受信起点、終端方針を維持。周期性能の未達を遅い周期へ変更して合格にしていない。
3. **全SPECから設計**: 機能13件・非機能6件のIDと設計対応を維持。
4. **全SPECから仕様テスト**: 既存の対応計画を維持。対象OS・対向条件・GUIを満たさない実施は部分検証とした。
5. **全DESNから設計テスト**: HW5件・SW14件のIDと計画を維持。自作実行コードのクラス／関数へ設計IDコメントを付けた。
6. **双方向Traceability**: 仕様19件・設計19件・計画73件（仕様36件、設計37件）のIDを再利用せず維持。実施した範囲と証跡を結果書へリンクした。79 pytestケースを計画73件の全合格と数えていない。
7. **未確認事項**: 電気測定はユーザー指定どおり保留。Windows、GUI操作、外部Classical受信、相手アプリ受信、停電・高負荷・PWMを未実施とした。周期精度を未達と明記。
8. **結果の実在性**: 79件の実機なし試験、実CAN2ケース、内部ループバック50条件、120秒ログ、配置SHA照合を実施。NormalモードのTEF成功と相手アプリのデータ受信を混同しない。CANエラー0とSPI CRC再試行2回を分けて記録した。
9. **OPEN管理**: 12件closed・6件pending。OPEN-014の実装開始許可を反映し、残る005／010／011／012／015／018を受入や将来統合の課題として維持。

## 修正と検証

停止以前に受付けた開始要求の抑制、置換の世代更新、TEF未完了100 msの停止、再接続時の旧SESSION_END・RX排除、部分USB書込み、異常時のCAN reset、ID別受付表示を実装した。CRC・頻回レジスタ読出し・JSON字句解析・USBバッファ移動へnative／Viperを適用した。CRC既知値、実機Buffer移動、全合法長ループバックで確認した。

120秒でTX_DONE 9,977／RX 1,440／周期skip 3,351、ログ欠落0。100 ms±2 msの評価目標は未達。CPythonの文カバレッジ51.31%、分岐43.02%で未到達経路が残る。GUIは起動確認のみで、操作ツールがウィンドウを取得できず適合判定をしていない。

最終配置8ファイルのSHA-256一致を確認。CANをConfigurationモード、稼働IDなしで残した。自動再開はしない。受入完了・正式1.0.0の発行・commit・pushは行っていない。
